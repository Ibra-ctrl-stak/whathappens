# whathappens

**Посмотрите на свой собственный запрос — байт за байтом.**

[English](README.md) | Русский

Вы десятки раз читали «что происходит, когда вводишь google.com».
`whathappens` действительно это делает: разрешает DNS начиная с корневых
серверов, открывает TCP-соединение, проходит рукопожатие TLS 1.3 и
говорит по HTTP/1.1 — а затем раскладывает *ваш* запрос в браузере на
шкалу с пояснениями. Байты на экране — это байты, прошедшие через вашу
сеть: ваши DNS-ответы, ваш ClientHello с SNI, сертификат вашего сервера,
ваш первый HTTP-ответ. Без root, без Wireshark, без телеметрии.

```sh
npm run day1 && npm run serve
```

![шкала, hex-вид и дерево полей](docs/screenshot.png)

## Что он делает

1. **Итеративный DNS своими пакетами.** Без `dns.lookup`: корневой сервер → `.com` →
   авторитативный, на собственных UDP-датаграммах (RFC 1035). Потерянные и битые ответы
   не прячутся, а остаются в записи.
2. **Записывает TLS-сессию.** `tls.connect` поверх прокси-потока: шифротекст в обе стороны,
   ключи сессии из официального события `keylog`, открытый текст, который отдал Node.
3. **Расшифровывает сам.** TLS 1.3 по RFC 8446 (HKDF-Expand-Label, ключи эпох, AEAD) —
   независимо от TLS-стека Node, только криптопримитивы `node:crypto`.
4. **Разбирает поля.** ClientHello/ServerHello с расширениями (SNI, ALPN, key_share,
   supported_versions…), сертификаты (`X509Certificate`), CertificateVerify, NewSessionTicket,
   HTTP-заголовки. У каждого поля — свой диапазон байтов; каждый байт принадлежит ровно
   одному полю.
5. **Проверяет подписи.** Цепочка сертификатов до корня из хранилища Node и подпись
   CertificateVerify над восстановленным транскриптом рукопожатия.
6. **Показывает всё на странице.** Шкала событий, hex-вид, дерево полей: клик по полю
   подсвечивает его байты, клик по байту — его поле.

## Быстрый старт

Нужен Node.js 24 (проверено на 24.20). Зависимостей нет.

```sh
git clone https://github.com/Ibra-ctrl-stak/whathappens.git
cd whathappens
npm test                      # 179 тестов, без сети
node day1.mjs                 # живой прогон: DNS → TLS → своя расшифровка → out/
npm run serve                 # страница на 127.0.0.1 (адрес с токеном — в консоли)
npm run timeline              # та же шкала текстом в терминале
```

Без живого прогона страницу можно открыть на эталонной сессии:
`node serve.mjs test/fixtures/github-robots/session.json`.

### Сверка с Wireshark (необязательно)

С установленным Wireshark (tshark/dumpcap): запишите захват во время `node day1.mjs`, затем
`node compare-wireshark.mjs out/capture.pcapng` сравнит байт в байт DNS, оба TCP-потока,
рукопожатие и расшифровку самого Wireshark по нашему keylog. Если трафик идёт через VPN,
захватывайте интерфейс туннеля.

## Как проверено

- **Wireshark как независимый оракул.** Эталонная сессия совпала с захватом байт в байт
  (12/12 проверок); значения полей в `test/fixtures/github-robots/expected.json` выдал tshark,
  а не наш код.
- **RFC 8448.** HKDF, ключи и расшифровка записей — по официальным векторам, извлечённым из
  текста RFC программно.
- **Повреждённый трафик.** Испорченные, оборванные и битые записи и сообщения остаются на
  шкале событиями с пометкой «повреждено», не роняя остальное.
- **Мутационные проверки** ключевых тестов: тест должен падать на намеренно сломанном коде.

## Безопасность и этика

- Инструмент видит **только трафик, который создал сам**, и расшифровывает его ключами своих
  же сессий через официальный API Node.js. Никакого перехвата и обхода защиты.
- Живые записи (`out/`: захваты, keylog, `session.json`) в git не попадают (`.gitignore`).
  Единственное исключение — эталонная тестовая сессия: ключи одной публичной сессии
  (`robots.txt`), см. [README фикстуры](test/fixtures/github-robots/README.md).
- Локальная страница: только `127.0.0.1`, случайный порт, 256-битный токен в адресе, проверка
  `Host`/`Origin` (защита от DNS rebinding), строгий CSP без inline-скриптов, DOM только через
  `textContent`. Странице не отдаются ни keylog, ни сессия целиком.
- Текст из сети (DNS-имена, HTTP-заголовки) экранируется: управляющие символы видны как
  `\xNN` и не действуют на терминал или страницу.

## Ограничения

- Только TLS 1.3 (AES-GCM, ChaCha20-Poly1305), HTTP/1.1, IPv4 и A-записи.
- Слой TCP (SYN/ACK, потери, ретрансмиты) Node не видит; его даст опциональный режим захвата
  (в работе, см. план).
- Не поддерживаются HelloRetryRequest, KeyUpdate, TLS 1.2, chunked/gzip-декодирование тела.
- Некоторые VPN-клиенты блокируют `127.0.0.1` для браузера — тогда страница не откроется.

## Устройство

| Путь | Что там |
|---|---|
| `src/dns/` | DNS-пакеты и итеративный резолвер |
| `src/tls/` | запись сессии, расшифровка, поля рукопожатия, сертификаты и подписи |
| `src/http/` | разбор HTTP/1.1 и его поля |
| `src/timeline.js` | единая шкала событий `{ buffer, offset, length, fields }` |
| `src/server/`, `web/` | локальная страница |
| `test/` | тесты, фикстура, векторы RFC 8448 |
| `tools/` | извлечение оракула из tshark и векторов из RFC 8448 |

Ход работы и следующие шаги — в [PLAN.md](PLAN.md).
