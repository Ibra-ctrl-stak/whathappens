# whathappens — план

Учебный визуализатор собственного трафика: DNS → TCP → TLS → HTTP, байт за байтом.

## Сделано

- **День 1** — проверка на смерть: итеративный DNS по своим UDP-пакетам, запись TLS-сессии
  через прокси-Duplex + `keylog`, своя дешифровка TLS 1.3; байт-в-байт совпадение с Wireshark.
- **День 3** — фундамент: единая шкала событий с диапазонами `[buffer, offset, length]`,
  эталонная сессия с оракулом от tshark, векторы RFC 8448.
- **Перед Днём 4** — ревью (code + security) закрыто: проверка DNS-ответов (порт, QR,
  вопрос), лимиты резолвера, фрейминг HTTP по Content-Length, повреждённые события вместо
  падения шкалы, экранирование управляющих символов, дыры в тестах.

## День 4 — разбор полей (сделано)

- Модель поля `{ name, offset, length, value, label, children }` (`src/fields.js`); дети
  всегда без зазоров покрывают родителя — проверяется для каждого поля каждого сообщения.
- Координаты: TLS-поля — позиции в handshake-потоке направления
  (`decryptSession().client|server.handshake`, индекс `messages`); HTTP-поля — позиции в
  расшифрованном потоке (буфер шкалы `http/out|in`).
- ClientHello / ServerHello / EncryptedExtensions с расширениями (SNI, ALPN, key_share,
  supported_versions и др.), Certificate (+ `X509Certificate`), CertificateVerify, Finished,
  NewSessionTicket, HTTP (стартовая строка, заголовки по байтам, тело).
- Подписи: цепочка (каждый подписан следующим, последний — корнем из хранилища Node, имя
  хоста, сроки на момент записи) и CertificateVerify над хэшем восстановленного транскрипта.
- Эталонная сессия перезаписана; оракул tshark расширен под все новые поля.

## День 5 — визуализатор (localhost) (сделано)

`npm run serve` → страница на 127.0.0.1 со случайным токеном. Срез 1: шкала событий с
фильтрами по слоям и пометкой повреждённых. Срез 2: hex-вид выбранного события (смещения в
координатах буфера, 16 байт в строке, печатаемый ASCII). Срез 3: дерево полей рядом с hex;
клик по полю подсвечивает его байты, клик по байту выбирает его единственное поле-лист.
Проверено в браузере пользователем (у агента headless-браузер блокирует VPN на 127.0.0.1).

Обязательные требования безопасности (из ревью):
- весь текст из сети — только через `textContent`, никогда `innerHTML`; тело ответа — hex
  или экранированный текст, не HTML;
- CSP `default-src 'self'`, без inline-скриптов;
- сервер только на `127.0.0.1`, случайный порт или токен в URL, проверка `Host`/`Origin`
  (защита от DNS rebinding);
- keylog и сырой `session.json` странице не отдавать.

## День 6 — слой TCP и крайние случаи

- Режим «с захватом» (dumpcap): SYN/ACK, потери, ретрансмиты, VPN-туннель. Захват
  **опционален** (решение уже принято); обычный запуск без dumpcap/Npcap.
- HelloRetryRequest, TLS 1.2 (`CLIENT_RANDOM`), chunked/gzip, KeyUpdate.
